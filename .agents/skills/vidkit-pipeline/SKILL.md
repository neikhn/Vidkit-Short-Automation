# Vidkit pipeline

Read the [video production checklist](references/video-checklist.md) at job start, when resuming and before each handoff, plus the [handoff contract](references/handoff-contract.md) and [CLI workflow](references/cli-workflow.md). Use `vidkit doctor`, `vidkit show <job-id>`, `vidkit diff <job-id> <language>` when a checkpoint exists, and `vidkit next <job-id> --language <language> --json` before acting. Existing jobs keep their workflow; new CLI jobs use v10. Do not edit SQLite or assume a missing stage is complete.

For each language, follow: research → script → creative brief with theme, hook, visual strategy, sourced assets and three frame previews → concept approval in review mode → final Eleven v3 narration → ElevenLabs STT word-level transcript → assets and caption plan → storyboard and motion → requested music/SFX and compiled mix → preview MP4 → QA report → export approval in review mode → render. Use `vidkit next` after every handoff.

Workflow v5–v7 includes a spoken follow-and-comment CTA with `cta-end-card`; v8 uses spoken Like and Subscribe with `channel-cta`. New v9 jobs use a topic-specific spoken follow-and-interact CTA with `channel-cta-strip`: display HCDB AI / say Hãy Cùng Bắt Đầu AI in Vietnamese, display and say AI Lens in English. The cursor clicks Like, Subscribe and bell on screen without those words being required in narration. Review the three-click motion, subtitle clearance and closing frame at concept and export review. Existing jobs retain their workflow and outputs.

New v6 jobs also center each scene's main visual group horizontally while keeping titles, headings and sources left-aligned. Review this during concept and final preview; custom code does not pass alignment QA without inspected frames.

For v7-v9 jobs, pick one `backgroundId` from `vidkit library search --kind background` after deciding the visual direction. Inspect `library show` and the still plus two-loop clip from `library preview`. Put the ID in the brief and storyboard; keep theme choice separate. Review the background beneath actual visuals and captions in concept and final previews. A background change requires fresh concept approval but reuses unchanged audio/STT. Existing jobs do not acquire a background automatically.

In review mode, “continue” means continue non-gated preparation only. Require explicit `vidkit approve ... concept` and `vidkit approve ... export` for the current revisions. In automatic mode, skip waits for video approval but never ignore validation failures; candidate library entries remain candidates. Do not promote a library candidate while approving a video unless the user separately chooses to do so.

Design how the viewer will understand each claim before searching the library. Analyze supplied references into observable editing choices and map each choice to a narrative beat. Compare two visual approaches for the main explanation, then select reuse, composition or new TSX code. A component may be job-specific; do not force content into an existing layout. Render a concept motion preview with `vidkit preview <id> <language> --stage concept` before concept approval. If a product screenshot is inaccessible, continue with sourced official artwork, an API example, chart or explanatory diagram. Label the evidence type and limitations accurately in brief and QA. Do not invent UI screenshots or logos.

Before modifying an existing video, inspect its current files, uncommitted changes and `vidkit diff`; preserve code already revised through Studio feedback. Use `vidkit checkpoint` for a named safe copy before broad edits. Put manually prepared material under `vidkit workdir <id> --language <language>`. After a workspace migration, work from the new paths and leave retained legacy copies untouched. If regeneration would discard revised code, show the concrete diff first. A successful render or passing probe is not proof of visual clarity.

Research and editorial work are agent tasks imported through the CLI. TTS and STT are paid API steps; do not send requests speculatively or repeat an uncertain result. No embedded LLM API, scheduler, automatic publishing, music beat detector, or budget guard exists.

When sound design is requested, include music/SFX direction in the creative brief and route to [sound effects](../vidkit-sfx/SKILL.md) and [background music](../vidkit-music/SKILL.md). The adapters load the official ElevenLabs [sound-effects](../sound-effects/SKILL.md) and [music](../music/SKILL.md) skills for provider guidance. Read the [sound contract](references/sound-design.md) for CLI/data. Generate/reuse sound assets after concept approval, then compile them with the timed storyboard before preview. Keep clean narration for STT. Sound generation is paid; unresolved attempts are recovered, not blindly retried. Music/SFX edits preserve narration/transcript and require a fresh mix/video review. The existing concept/export gates cover audio direction and final mix.

When the user requests SEO or publication metadata, route to [Shorts SEO](../vidkit-seo/SKILL.md) using the explicit job ID/language and currently approved clean script. It prepares manual `seo/` files under `vidkit workdir`, with three actual portrait A/B/C thumbnails by default (explicit `text-only` skips images) and independent SEO review. Description includes its hashtags in one copyable block; tags target 450–500 useful characters within the 500 cap. Missing image tools leave thumbnail work visibly incomplete. Do not add SEO to `next`, change workflow version, or gate preview/export on it. Recheck package/input and image checksums before publishing handoff; video approvals and automatic mode do not approve SEO. Read-only checks or publishing existing SEO do not generate images or upgrade version 1.

Route to [research](../vidkit-research/SKILL.md), [script](../vidkit-script/SKILL.md), [voice](../vidkit-voice/SKILL.md), [transcript](../vidkit-transcript/SKILL.md), [storyboard](../vidkit-storyboard/SKILL.md), [render](../vidkit-render/SKILL.md), and [publish](../vidkit-publish/SKILL.md) only as needed. Report actual artifact paths, revisions and unperformed QA checks.


For v10 jobs, read [layered background design](references/background-design.md) when choosing or extending backgrounds. A pattern is required; effects are optional. New candidates use still review first and motion review second. Do not render candidate clips before user feedback on the still images.
